The Core Problem in Plain Terms

Running Metabase on a traditional virtual machine (VM) means our team has to manually update the server, and the Metabase login page is visible to the public internet. However, moving to per-user cloud plans like Metabase Starter (~Rp 659M/yr) or Tableau (~Rp 1.69B/yr) either strips away our security audit logs or forces us to spend 3 to 6 months rebuilding 407 dashboards from scratch.

Top 3 Practical Paths for Modinity

Recommended Option A: Serverless GCP Upgrade

Metabase Free on Google Cloud Run + Google IAP

~Rp 30.2M / yr (~Rp 2.5M / month flat)

Instead of paying a vendor Rp 1.4B/year to manage a server, we move our existing free Metabase out of a traditional VM onto Google Cloud Run behind a Google Employee Login Gate (IAP).

  • Hackers cannot reach Metabase: Google blocks all internet traffic at the front gate unless the user is already signed into an official @modinity.com Google account.
  • Zero server maintenance: Google manages the database (Cloud SQL), and an automatic weekly job updates Metabase with zero downtime.
  • Zero disruption: Keeps all 407 dashboards, 7,365 charts, audit logs, and AI tools intact in 2 to 3 hours.
Recommended Option B: Turnkey Vendor SaaS

Metabase Pro Cloud (Official Managed SaaS)

~Rp 1.39B / yr (Rp 97.6M -> Rp 133.5M / mo)

If leadership prefers a 100% vendor-hosted SaaS contract with official SOC 2 compliance and built-in Row-Level Security, Metabase Pro Cloud is the only cloud upgrade that does not downgrade our capabilities.

  • 1-day migration: Uses Metabase's built-in Cloud Migrator to copy all 407 dashboards and 7,365 charts automatically.
  • Keeps all AI & Audit features: Preserves 100% of Antigravity AI dashboard creation, Gemini Enterprise (ge-mcp), and built-in Usage & Audit Logs.
  • Unlocks Row-Level Security: Lets a single dashboard automatically filter rows based on which brand an employee belongs to.
Why the Other Options Fall Short

Starter, Lightdash & Tableau Trade-Offs

Rp 583M to Rp 1.69B / yr

Each of the remaining options introduces a major operational or security penalty:

  • Metabase Starter (~Rp 659M/yr): Costs half a billion Rupiah per year while deleting our security audit logs (we can no longer see who viewed or exported data) and adding zero new security features over Free.
  • Lightdash Cloud (~Rp 583M/yr): Flat-rate pricing for unlimited users, but cannot connect to our live Odoo ERP alongside BigQuery, blocks quick custom SQL charts, and requires rebuilding all 407 dashboards.
  • Tableau Cloud (~Rp 1.69B/yr): Requires a 1-year upfront contract, locks 408 users into read-only mode, breaks our AI tools, and requires 3 to 6 months of manual rebuilding.
Chapter 02 / Recommended Architecture Upgrade

Metabase on Google Cloud Run + Google Login Wall (IAP)

How we eliminate manual VM patching and public internet exposure for ~Rp 2.5M/month while keeping 100% of our 407 dashboards and AI workflows.

Option 1: Current Virtual Machine (VM) Setup

Like a House with the Front Door on a Public Street

Today, Metabase runs inside a standard Virtual Machine. While it works well, it has two classic operational headaches that concern IT leadership:

1. Public Internet Can Reach the Metabase Login Page Anyone on the internet can send web requests to modisight.modinity.com. If a new software bug is discovered in Metabase before we update it, external bots can probe the login screen or API.
2. Manual Server Maintenance An engineer has to log into the server to update Linux, manage disk space, and pull new Metabase updates.
3. Database Lives on the Same Setup Backup recovery and database maintenance depend on our internal server scripts.

Like a Vault Inside Google's High-Security Building

We delete the Virtual Machine completely and run the exact same free Metabase software inside Google's serverless infrastructure:

Case Study / Replay of the August 2026 Incident

What Would Have Happened in August 2026 on Cloud Run + Google IAP?

The August 2026 incident succeeded because three specific weaknesses lined up at the same time on our Virtual Machine. Here is what happened on the VM versus what happens on Google Cloud Run + Load Balancer (Google IAP & Cloud Armor):

August 2026 Failure Point What Happened on the VM (August 10 to 13, 2026) What Happens on Cloud Run + Google IAP
1. Unauthenticated Attack on Password Reset API Reached Metabase Directly
An external automated scanner sent 483 requests to POST /api/session/reset_password without logging in, using a SQL injection bug (CVE-2026-72898) to create admin sessions.
 100% Blocked at Google's Gate
With Google IAP active, Google checks for a valid @modinity.com login with 2FA before forwarding any request. All 483 unauthenticated requests are rejected by Google with 401 Unauthorized before touching Metabase. Cloud Armor WAF (sqli-v33-stable) also blocks SQL injection payloads at the edge.
2. Accidental Open Port 3000 Firewall Bypass Bypassed Web Server
A broad GCP firewall rule (airflow-8080) meant for another tool accidentally opened port 3000 across all VMs. The attacker connected straight to the VM IP on port 3000, bypassing nginx completely.
 Physically Impossible
Cloud Run is serverless, has no public VM IP or open ports like :3000, and ignores GCE VM firewall rules. With ingress locked to internal-and-cloud-load-balancing, no one can bypass Google's Load Balancer or IAP.
3. 4-Day Patch Delay (Aug 6 Fix vs. Aug 10 Attack) Waiting for Manual SSH Update
Metabase published the security fix (v0.63.5) on August 6. Our VM was still on v0.63.1 four days later on August 10 because updates required manual engineering intervention.
 Automated 24h Container Refresh
Because dashboards live in managed Google Cloud SQL, the Cloud Run container is stateless. An automated schedule pulls the latest patched Metabase release and deploys a fresh container automatically with zero downtime.
Future Resilience / Unpatched Zero-Day Scenario

What If a Brand-New "Zero-Day" Bug Happens Tomorrow (Before Any Patch Exists)?

A "zero-day" is a brand-new software bug that hackers discover before the software vendor has written a fix. Notably, before August 6, 2026, even official Metabase Cloud was exploited during the zero-day phase because its login page is open to the public internet. Here is how the three architectures hold up when no patch exists yet:

1. Traditional Public VM

Exposed Until Patched

Anyone on the internet can reach the Metabase login screen and API endpoints directly. If a pre-login zero-day bug drops, external bots can exploit it before a patch is released.

2. Official Metabase Cloud SaaS

Fast Patching, Public Login

Metabase's team patches their cloud servers first once a fix is written, which stops delayed-patching attacks. However, because *.metabaseapp.com login pages are public on the internet, pre-login zero-days can still reach the app before a fix exists.

3. Cloud Run Behind Google IAP

Shielded Even Before a Patch Exists

Even if Metabase has an unpatched zero-day bug tomorrow, an external hacker on the internet cannot reach Metabase at all. They hit Google's login wall first and are blocked unless they have a real @modinity.com account with 2-Step Verification.

When would we still need Metabase Pro Cloud (~Rp 1.39B/yr) instead of Cloud Run?

Only if Modinity specifically needs Row-Level Security (RLS) (where 50 store managers open the exact same dashboard URL and Metabase automatically filters the rows so each manager only sees their own store) or an external SOC 2 vendor certificate from Metabase. Today, we handle store and brand separation at Rp 0 cost using separate Metabase folders (Collections) and BigQuery views.

Chapter 05 / Alternative BI Tools

What Do We Lose If We Switch to Lightdash or Tableau?

Both Lightdash and Tableau are respected tools, but switching away from Metabase means giving up core workflows that Modinity uses thousands of times a day.

Option 6 Deep Dive: Lightdash Cloud Pro (~Rp 583M/yr Flat Fee)

Why Lightdash Looks Attractive on Paper, and What Actually Breaks

Lightdash is built specifically on top of dbt (the data transformation tool Modinity uses) and charges a flat monthly workspace fee (~$2,400 to $3,000/month) for unlimited users instead of charging per viewer. However, checking our live Metabase usage reveals 4 major capabilities we would lose immediately:

1. We Lose Instant Custom SQL Charts
4,446 Charts

61% of Modinity's charts are custom SQL queries built in seconds by analysts or AI. In Lightdash, charts are supposed to be defined in Git code files (schema.yml) first. Raw SQL charts in Lightdash cannot use standard semantic filters and cannot even be duplicated with a button.

2. We Lose Live Odoo ERP Reporting
242,098 Queries

In the last 90 days, Modinity ran 242,098 queries across 85 charts directly against our live Odoo database. A Lightdash project can only connect to one database (BigQuery). We could no longer combine live Odoo data and BigQuery data in one place.

3. Business Users Wait on Engineers
2,809 GUI Charts

In Metabase, as soon as a table exists in BigQuery, business users can click and summarize it (2,809 charts built this way). In Lightdash, a table or column is completely invisible to business users until a data engineer writes YAML code for it and deploys it.

Option 7 Deep Dive: Tableau Cloud Standard (~Rp 1.69B/yr Forecasted)

Why Tableau Is the Most Expensive & Disruptive Option

With 6 Creator seats ($75/mo), 0 Explorer seats, and 408+ Viewer seats ($15/mo), Tableau costs more than any other option while slowing down our data & AI delivery:

1. Requires 1-Year Upfront Contract
Rp 1.42B+ Upfront

Unlike Metabase or Cloud Run (which can be paid monthly), Tableau Cloud requires signing an annual contract paid upfront, locking Modinity in before a single dashboard is migrated.

2. Downgrades 408 Users to Read-Only
0 Explorers

In Metabase, all 414 users can build their own views and pivot tables. In Tableau, $15/mo Viewers are strictly read-only. Allowing brand or finance leads to build their own views requires upgrading them to $42/mo Explorer seats.

3. Breaks AI Dashboard Creation
407 Dashboards

Tableau dashboards are complex desktop files (.twb XML), not simple SQL cards. Even with tableau-mcp, AI cannot read chart SQL or update a single chart on a live dashboard, and our 6 analysts would spend 3 to 6 months rebuilding 407 dashboards by hand.

Chapter 06 / Implementation & Continuity

Zero Capability Loss & 1-Day Migration Plan

Whether we choose Option 2 (Cloud Run + Google IAP at ~Rp 30M/yr) or Option 4 (Metabase Pro Cloud at ~Rp 1.39B/yr), our team loses zero functionality and migration takes less than 1 day.

Will Creating Dashboards from Antigravity Change or Downgrade?

No. It works 100% identically in both Cloud Run and Metabase Pro Cloud. Our Antigravity workflow uses Metabase's standard web API (/api/card and /api/dashboard) to write SQL queries, create charts, and arrange 24-column dashboard layouts automatically. Moving to Cloud Run or Metabase Pro Cloud only changes the server URL and API key in our configuration file.

Rollout Plan A: Metabase on Cloud Run + IAP (~2 to 3 Hours)

How We Move to Serverless Google Cloud Run

  • Step 1 (30 mins): Create a managed Google Cloud SQL for PostgreSQL instance with automated daily backups inside our GCP project.
  • Step 2 (30 mins): Copy our existing Metabase database (all 407 dashboards, 7,365 charts, collections, and audit logs) into Cloud SQL.
  • Step 3 (45 mins): Deploy the official Metabase container onto Google Cloud Run connected to Cloud SQL, and enable the automated weekly version update job.
  • Step 4 (30 mins): Turn on Google Identity-Aware Proxy (IAP) on the load balancer so only signed-in @modinity.com Google accounts can reach the server, then switch the modisight.modinity.com domain over.
Rollout Plan B: Metabase Pro Cloud (~1 Day via Built-in Tool)

How We Move to Official Metabase Pro Cloud

  • Step 1 (15 mins): Open Admin -> Settings -> Cloud inside our current Metabase and click Migrate to Metabase Cloud.
  • Step 2 (Automatic): Metabase automatically packages all 407 dashboards, 7,365 charts, user accounts, and folder permissions into a cloud snapshot and provisions our new Pro Cloud instance.
  • Step 3 (1 to 2 hours): Re-enter database passwords (BigQuery service account and Odoo replica) in the new Cloud admin screen.
  • Step 4 (1 hour, handled by AI): Antigravity updates the URL and API key in our local MCP config, ge-mcp (Gemini Enterprise), and Modibot, and updates any audit queries to use Pro's Usage Analytics tables.

Summary Recommendation for Executive Decision

1. Approve Option 2 (Metabase Free on Google Cloud Run + Cloud SQL + Google IAP) as our immediate architecture upgrade. For ~Rp 2.5M/month (~Rp 30.2M/year), it removes manual VM maintenance, puts Google's authentication wall in front of Metabase so external attackers cannot touch the application, and preserves 100% of our 407 dashboards, audit logs, and AI tools.

2. Keep Option 4 (Metabase Pro Cloud at ~Rp 1.39B/year) as our turnkey SaaS option if Modinity later requires automated Row-Level Security (RLS) inside shared dashboards or external vendor SOC 2 hosting, knowing we can migrate to it in 1 day without losing any capability.
