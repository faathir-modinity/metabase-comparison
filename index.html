Why Unoptimized Pro Cloud Looked So Expensive: Dormant Seat Drift (+14/mo) vs. Real Active Growth (+2/mo)

Converting all 413 accounts unchecked costs Rp 97.4M/month today and balloons to Rp 1.37B/year (413 to 567 seats) if we keep adding ~14 gross accounts per month without offboarding. However, 10 months of live login_history (Feb to Nov 2026) prove that Modinity's true Monthly Active Users only moved from 310 to 329 (+2 net users/month). Roughly 85% of historical seat growth came from former interns, rolled-off KPMG consultants, duplicate logins, and one-off accounts that were never deactivated because self-hosted seats were free.

Chapter 05 / Implementation & Ongoing Cost Control

Pre-Migration Cleanup & Monthly Billing Governance

Four concrete steps so our very first Metabase Pro Cloud monthly invoice starts at 352 optimized seats ($4,679/mo) instead of 413 ($5,411/mo), and stays lean every month thereafter.

Phase 1 / Execute Before Clicking "Migrate to Cloud" (Day 0)

1-Hour Pre-Migration Seat Cleanup Checklist

  • Step 1 (Re-route 5 Tech Alert Pulses): Update Sync Sales Qty Shopify vs Odoo, Transfer Order Monitoring, and [Automated] Oracle Data Migration Tracker to send directly to an external/group email alias (such as tech-alerts@modinity.com) so recipients do not consume $12/mo seats.
  • Step 2 (Assign Groups to 4 Active Unassigned Users): Move the 4 active All Users Only accounts (2 store accounts, 1 staff, 1 new hire) into their proper permission groups for Least Privilege RBAC.
  • Step 3 (Deactivate 61 Idle Non-ExCo Accounts): Soft-deactivate (is_active = false) the 61 personal accounts with no login in >30 days and date_joined < NOW() - 14 days, keeping all 14 ExCo seats and 5 new joiners untouched.
  • Step 4 (Run Built-in Cloud Migrator): Trigger Admin -> Settings -> Cloud. Only the 352 active seats become billable on Month 1; all 407 dashboards, 7,365 charts, and 5 free programmatic API keys carry over intact.
Ongoing Hygiene / Automated Monthly Billing Guardrail

How We Prevent Seat Drift on Monthly Billing

  • Automated 28th-of-Month Seat Audit: Run a lightweight scheduled script (Airflow DAG on modibt) 48 hours before each monthly billing cycle using Metabase Pro's Usage Analytics API (/api/user) to auto-deactivate non-ExCo accounts idle >30 days.
  • Frictionless 1-Click Reactivation: Because Metabase deactivation is non-destructive, any returning employee simply pings BI/IT (or logs in via Google SSO + Pro SCIM group rules) to restore their exact account in seconds.
  • Enable SCIM / Google Group Sync on Pro: Metabase Pro includes SCIM provisioning, so HR/IT offboarding in Google Workspace automatically revokes the $12/mo Metabase seat the same day an employee leaves.
  • Q1 2027 Phase 2 Option (Store Guest Embeds): If leadership wants to cut monthly billing further from Rp 84.2M/mo to Rp 57.7M/mo, pilot a lightweight Cloud Run store viewer using Pro's included JWT Guest Embeds ($0/viewer) for the 123 store accounts.
Reference SQL / Automated Monthly Seat Pruning Query

Exact Candidate Query Used for This Audit (30-Day Cutoff + ExCo & 14-Day Grace)

-- Returns the exact 61 non-ExCo seats eligible for soft deactivation via DELETE /api/user/:id
SELECT
  u.id,
  u.email,
  u.date_joined,
  u.last_login,
  ROUND(EXTRACT(EPOCH FROM (NOW() - u.last_login)) / 86400.0, 1) AS days_idle
FROM core_user u
WHERE u.is_active = TRUE
  AND u.type = 'personal'
  AND u.date_joined < NOW() - INTERVAL '14 days'               -- 14-day onboarding grace (protects 5 new joiners)
  AND (u.last_login IS NULL OR u.last_login < NOW() - INTERVAL '30 days')
  AND NOT EXISTS (                                             -- Exempts all 14 ExCo members
    SELECT 1
    FROM permissions_group_membership pgm
    JOIN permissions_group pg ON pg.id = pgm.group_id
    WHERE pgm.user_id = u.id AND pg.name = 'ExCo'
  )
ORDER BY u.last_login NULLS FIRST;
